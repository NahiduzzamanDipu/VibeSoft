# Interaction Design

Start from the user's goal and the product's state model. Map the normal path plus empty, loading, success, error, disabled, and interrupted states that apply.

- Make actions discoverable and feedback timely. Preserve entered data and provide recovery for errors where possible.
- Use semantic controls and predictable keyboard behavior; keep focus visible and manage focus in dialogs and menus.
- Prefer native behavior unless a custom interaction has a clear user benefit.
- Treat hover as supplemental; touch and keyboard users need equivalent operation.
- Keep transitions brief and state-driven. Do not make core meaning depend on motion or color alone.
- Check the full flow at narrow widths and with realistic content.

Describe behavior and edge cases before complex implementation. Verify interaction with the browser or tests when available and report which states were actually exercised.
