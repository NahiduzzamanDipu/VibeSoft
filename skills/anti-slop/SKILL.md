# Anti-Slop Design Transformation

Make the design belong to its product. Do not merely remove decorations: establish a stronger visual idea from the product, audience, content, and brand, then implement it in the existing stack.

## Audit and direction

Inspect the actual screen and its source when available. Record findings with location and impact. Look for generic signals such as a repeated centered hero, three identical feature cards, unnecessary gradients or glow, excessive rounded surfaces, default type without reasoning, emoji icons, decoration without meaning, generic dashboard grids, weak hierarchy, and repetitive animation. Treat each as a question. Keep it when the brief or established design language justifies it.

Before editing, state a compact design direction: product-specific visual idea, type roles, color roles, content hierarchy, layout rhythm, focal detail, and motion intent. Preserve user content and working flows. Prefer a few meaningful changes to a pile of stylistic effects.

## Transformation pass

1. Fix information hierarchy and page structure against the primary user task.
2. Establish meaningful type scale, text measure, palette, contrast, and spacing rules.
3. Remove repetitive or purposeless components; retain cards and familiar layouts only when they aid scanning or task grouping.
4. Use product-relevant imagery, data, or illustration; do not invent fake product screenshots or decorative imagery.
5. Add interaction feedback and motion only when it clarifies state or adds a brief-specific moment. Respect reduced motion.
6. Check responsive layouts, focus, keyboard use, empty/error/loading states, and content overflow.

## Evidence

When available, run the app and compare screenshots before and after at representative widths. Record the specific defects fixed and what was inspected. If the app could not be launched, say the visual result remains unverified. No style pattern is banned by this skill; the product brief and user needs decide.
