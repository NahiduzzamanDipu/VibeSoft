# Responsive Design

Inspect the existing breakpoints and layout before changing them. Let content and task needs determine when the layout changes; do not target device names alone.

- Preserve information priority and primary actions at every supported width.
- Reflow navigation, columns, tables, media, forms, and dialogs rather than shrinking desktop blindly.
- Check long labels, localization, user-generated content, zoom, and narrow viewport overflow.
- Provide usable touch targets and avoid hover-only behavior.
- Use flexible sizing and existing responsive tokens; avoid scattered arbitrary breakpoints.
- Check orientation and intermediate widths when they expose layout transitions.

When possible, inspect screenshots at named viewport widths and verify core actions. Report overflow, hidden content, and any untested sizes explicitly.
